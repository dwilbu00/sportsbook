## Refit / candidate-staging workflow (commit 461af91)
Refits no longer touch the live file. Flow: (1) `python refit_calibration.py --sport mlb ...` STAGES to `calibration/mlb.candidate.json` (all 5 offline CLI mains stage: refit_calibration, backtest `--write-calibration`, backtest_props/starters/nfl_epa `--save`); (2) `--diff` review; (3) `--promote` (archives live → `calibration/archive/`, atomic replace) or `--discard`; `--live` is the escape hatch. Candidate mode is process-global default OFF → byte-identical for app runtime / forward_tracker / online loop / tests; serving readers always read live. Staged saves ACCUMULATE into one candidate. `calibration/*.candidate.json` + `archive/` gitignored; live JSON committed.

- ⚠ **INCUMBENT HYSTERESIS** (still true, now largely defanged): a bare synthetic re-sweep resets every incumbent to A, and `--real-lines` then CANNOT rebuild a within-gate-band real-line method (a method beating A by <0.002 stays lost). Candidate-staging means this now lands in the candidate (visible in `--diff`, don't promote) instead of clobbering live — but still splice/verify the winner back as incumbent before promoting. Sweeps reset non-A incumbents to A, so EXCLUDE tuned props (batter_hits E, pitcher_strikeouts E) from a sweep or splice them back before `--real-lines`.
- **Gates:** method selection = beat A's unconditional Brier by `MIN_CALIB_BRIER_GAIN=0.002` on a single 50/50 chronological holdout AND confirm in BOTH expanding folds (`_confirms`). `MIN_REAL_LINE_OVERRIDE_OBS=500` incumbent protection (blocks thin-prop churn; `--min-override-obs` flag adopts a confirmed-better method just under the floor). **ROI-as-tiebreaker** (88b8671 + `best_roi>0` guard 5c3eb56 + cross-fold guard f099e2f): when ≥2 methods land within 0.002, realized flat-1u ROI at de-vigged consensus prices breaks the tie — Brier stays primary, override only past 15-bet floor + 0.02 ROI margin + winner must be +ROI in BOTH folds.
- **Refit cadence signal:** prediction_log `refit_performed` BIT + once-per-session app banner nudges a refit when ≥200 newly-resolved MLB rows accrue. Stale scratch/DNP predictions auto-voided after 24h (`STALE_DNP_HOURS`).
- Offline CLI mains MUST call `db_store.promote_secrets_from_toml()` first or they run against the empty local store (silent no-op on prod SQL).

## Feature experiments — ALL ship nowhere (retired, free-recheckable as warehouse grows)
Every curated feature was evaluated through the 2-fold + 0.002-margin gate via the no-write `--feature-diag`/`--negbin-diag`/`--roi-diag`/`--dist-diag`/`--center-diag` lenses. Verdicts (all built INERT, auto-re-check as data accrues):
- **rest/days-off, platoon, gamecontext, xBA-mean-blend@0.5** — all correctly signed but ~10× under the 0.002 gate at line 0.5 (P(≥1 hit) saturation absorbs them). xBA/method-B DOES pay at line ≥1.5 (Brier 0.2315→0.2194) but those buckets are too thin for the 2-fold gate. Platoon's optimum ~strength 0.3 peaks at +0.0001 Brier.
- **NegBin variance / "method G" (context-conditional dispersion)** — KILLED before build: batter_hits NegBin dispersion fits 0.0000 (the Poisson floor — the sample is NOT over-dispersed), reconfirmed twice. E's edge is Poisson count structure + ROI-tiebreak, not variance.
- **median-vs-mean center** — median LOSES everywhere; the MEAN is the correct distributional parameter for these count props. Do not swap.
- **Additive lineup-offense into team predictions** — REFUTED: monotonically worsens ML/spread Brier at every weight (model already encodes offense; additive layer double-counts + amplifies overconfidence). Only a REPLACE-the-offense-term bottom-up runs model is worth revisiting (insertion point mlb_starters.py:1347-1350).
- Also dead: home-AB delta (direction right, magnitude ~−0.2 not shippable), rolling-window xBA (noisier than season-to-date), CSW-blend for pitcher_strikeouts, per-bucket feature-ship asymmetry (measured, not just data-starved).
- **Suppress batter_hits UNDER @ line 0.5** — model's under-lean is anti-predictive (~43% OOS win, −EV); recommendation-side filter, empirically confirmed.

## Team-market audit verdict (the big one)
Honest 4-season backtest on the dense DK closing-line warehouse + code-grounded audit: **the MLB team model sits AT the efficient-market variance floor (~0.24-0.25 Brier), NOT far below it.** Model Brier is worse than market on all 3 markets and is monotonically overconfident (says 90%+, wins ~57-65%). No durable global mean edge exists on team markets.
- **Overconfidence cause = the POINT ESTIMATE is too extreme** (over-extreme recency+pythag), cured by SHRINKAGE not variance. The pred_std floor was a measured NO-OP (pred_std already ~5.9 ≥ empirical 4.52) and was reverted. Shrink + Pythagorean 0.35 are both LOAD-BEARING mean-reversion, validated (unshrink LOSES at every gate; releasing pythag collapses the false-confident tail).
- **The lever sweeps are EXHAUSTED.** OOS (`--oos-ab` train 2023-24 / test 2025-26): honest ML edge ≈ **+3.3%** at EV≥12% (~32% of games), unstable across seasons, in-sample peak was +7% (overfit tax ~half). Keep shrink, keep pythag 0.35 (unstable across windows — do NOT re-tune off one window), spreads UN-disqualified (marginal +, was a challenger-OFF harness artifact), totals marginal. Selection lever = the EV gate (EV≥8-12%). Global knob-tuning has diminishing returns + overfit risk → **the real edge is SITUATIONAL, not global.**
- **★★★ SBR odds-source confound (proven):** the entire pre-mid-2025 SBR-sourced backtest history was unfairly pessimistic — same 2024 games, model Brier IDENTICAL, ONLY prices differed: ML swung −8.6% (SBR) → +1.2% (clean API). Many "team model loses everywhere" verdicts were partly an SBR artifact. Note: 2023 is now fully PURGED and stores are warehouse-only (2024-2026); the confound is a durable methodological lesson, but the api2024/SBR data itself is gone. Prefer 2024+ for evaluation; 2023 was also a pitch-clock/shift-ban regime outlier.
- **Harness faithfulness fixes shipped** so the backtest grades what production runs (as-of season-runs feed the pythag blend; ERA-proxy staff lets the spreads challenger fire). Backtest leakage fixed: pitcher/lineup stats are now warehouse-native as-of (was full-season look-ahead).
- **The two remaining paths to team value:** (1) selection/disqualification (tighter gate + heavy shrink for ML; spreads marginal); (2) **market-upset study** — find WHERE the close is systematically wrong (situational, not a better global projection). The agreed roadmap: diverge boldly (don't over-suppress) → select among divergences (upset study → disqualification classifier) → bet EARLY at CLV advantage. This is mostly the edge-strategy/market-upset domain now; see those memos. The situational upset study is the live next step, using the model's own calibration-junction disagreements (|raw p − market p|, pre-shrink pred_std, recency-vs-pythag gap) as free per-game features.

## Forward-vs-backtest Brier — diagnosis CONFIRMED (adversarially verified)
The "forward worse than backtest" complaint is **almost entirely a pitcher-prop artifact**: pitchers are fit/selected on SYNTHETIC season-average lines but graded forward on REAL book lines, plus they have ZERO online Platt (only batter_hits does). batter_hits (real-line fit + big-n + live Platt, 83% of volume) tracks cv within ~0.002. Live gap ladder (2026-08-07): batter_hits fit 0.2409/cv 0.2411/fwd 0.2432; pitcher_outs 0.2201/0.2256/0.282 (textbook in-sample-optimism). Winner's-curse over the 576-variant sweep is a secondary REPORTING concern (<10% of the pitcher gap), not the driver. Regime change and grading corruption RULED OUT. **A "reset to 2026-only training" is a NO-OP** — calibration is already `fit_season=2026` with strict-season priors, and a bare reset would discard the working batter_hits E + its Platt (risks the incumbent-hysteresis E→A demotion). What actually helps: (a) grow pitcher REAL-line obs so they leave synthetic_sweep; (b) seed/enable pitcher online Platt; (c) report cv_brier not fit_brier for tiny-n props; (d) treat the negative-ROI/sub-50%-directional-hit issue as an EDGE problem, not a calibration-window problem.

## Guiding principles + constraints
- **★ KEEP-IF-IT-IMPROVES-THE-MODEL (core principle, Doug 2026-09-09).** Two SEPARATE goals, never conflated: (1) a BETTER MODEL = better OOS prediction/calibration (Brier/log-loss/ECE) — kept for its OWN sake (honest EV, reliable decisions, suppressing phantom edges, a coherent framework); (2) an EDGE = beating the market (ROI/CLV), which lives in market-structure/soft/transient lines, NOT in better prediction. **We KEEP an idea if it makes the model better OOS — PERIOD — even if it never beats the closing market.** We only DROP an idea if it fails to improve PREDICTION OOS (e.g. NFL injuries/opponent-adj/turnovers — dropped for not helping prediction, NOT for lacking an edge). The isotonic recal + the opportunity-first builds (TB/RBIs/pitcher/team-runs) are kept on this basis: calibration-only is a FEATURE (honest probs → correct abstention), not a reason to abandon.
- **Calibration (Brier) ≠ profitability (ROI/CLV).** Against an efficient close, minimizing Brier drives you ONTO the market line = zero edge. But per the principle above, that's fine — a market-matching honest prob is STILL worth having (it stops us betting miscalibration-driven fake edges). The edge is a SEPARATE hunt (market-structure/situational/transient), not a reason to discard a prediction improvement.
- Treat calibration as ONE slot (scalar-shrink OR Platt OR blend), chosen by OOS comparison, NEVER stacked — shrink + blend are both market-anchoring and double-anchor if combined.
- Pure stdlib only (no numpy/pandas/scipy; `math.lgamma` covers NegBin). Streamlit reruns whole-script → cache per-game work. Offline sweeps run on the owner's warm 16-core machine off the warehouse; Cal writes commands, owner pastes output.
- Data is warehouse-only, 2024-2026 (read via db_store / r2_* stack / `--source warehouse`). 2023 purged, local-JSON stores dead. Betting is DraftKings AND FanDuel (both executable); Pinnacle/other books are analysis-only.
