**Independent review — Sportsbook, 2026-09-08**

Reviewed checkout: `ec6826c` on `main`. The working tree was clean at the start. Scope: the NFL and MLB claims in `HANDOFF.md`, the current local mirror, validation/settlement code, calibration workflow, and the app's feature-to-prediction wiring. This is a review, not a model promotion. No production model, calibration file, source data, database, or betting configuration was changed. No paid API requests were executed.

**Verdict: retain “no durable betting edge has been demonstrated.” Withdraw “fully leakage-free,” “replicates every season,” and “proven irreducible prediction ceiling.”** There are concrete defects behind those stronger claims. The NFL market benchmark still wins after the timing corrections I tested. I did not uncover a validated profitable strategy. I did uncover an untested correction that improves the totals model and a supposedly replicated MLB survivor that is actually a single-season result.

The most consequential findings follow. P1 means address before relying on the affected result or serving path; P2 means a material diagnostic, validation, or maintenance defect.

1. **[P1] NFL backtests use a quarterback identity determined by the game being predicted.** `nfl_qb_asof.py:147-160` chooses the passer with the most dropbacks in the completed game. That is not necessarily the announced starter. The local data contains 46 team-games in 2023-25 where this differs from the first recorded passer: examples include Aaron Rodgers/Zach Wilson, Anthony Richardson/Gardner Minshew, and Deshaun Watson/PJ Walker. The latter two include games beyond the excluded first week. Injuries and benchings during the game can therefore determine a pregame feature.

   The EPA ratings themselves use prior games; that does not make the selected identity safe. My re-fit/re-score sensitivity check produced pooled LOSO RMSE 13.18545 using the existing majority-passer definition and 13.19897 using the live projected-starter path. The difference is small, but a small impact does not erase leakage. A first-passer proxy scored 13.17271; that proxy is also retrospective and is not a substitute for an announcement timestamp. Use a pregame-known starter or the identical projection available at the simulated decision time, and re-fit with it. Reproduction: `nfl`.

2. **[P1] The NFL “clean closing” corpus contains post-kickoff and stale observations that the loaders accept.** `nfl_market_scan.py:62-103` selects `source == snapshot` without checking `captured_at <= commence_time`; `nfl_props_scan.py:84-108` has the same weakness. The DK team mirror across calendar files 2023-26 contains 22 closing rows across five events captured after kickoff, and 31 events with closing captures more than an hour before kickoff. The maximum lead is 457.38 minutes. Examples: Kansas City at Jacksonville on 2023-09-17 is captured 42.67 minutes after kickoff; Cincinnati at Buffalo on 2025-12-07 is captured 188.07 minutes after kickoff. The props files also contain post-kickoff rows: 76 in calendar 2023 and 78 in 2025.

   This is an observed data problem, not a hypothetical missing guard. A successful game-ID join proves identity, not information availability. Reject post-start captures, retain provenance, and separately label stale pregame quotes. Do not use the same label for all three. My strict benchmark below still favors the market, so these contaminants do not rescue the current margin model. Reproduction: `benchmark`; props counts can be checked using the same timestamp comparison on the props mirror.

3. **[P1] MLB's lone “replicating” survivor has only one season of evidence.** `scenario_backtest.py:916-922` uses `bool(judged) and all(...)`, so one positive season qualifies as “replicates.” Re-running the actual `scenario_prop_roi` path for `batter_strikeouts UNDER 1.5` over requested seasons 2024, 2025, and 2026 reproduces **9,179 bets, +1.25794% ROI, t=1.68705 — all in 2024**. The local 2025 and 2026 DK prop mirrors contain no `batter_strikeouts` rows.

   Thus the reported number is reproducible, while its claimed replication is false. Even before accounting for the search across cells, the approximate ordinary 95% interval is -0.20% to +2.72% ROI. Dependence and selection can make uncertainty greater. Require multiple adequately populated independent periods, print every requested season including zero-coverage seasons, and classify this as an exploratory 2024 result. Reproduction: `mlb`.

4. **[P1] MLB real-line calibration can grade the wrong game despite an explicit game ID.** In `book_line_calibration.py:462-488`, an explicit `game_pk` absent from the player's gamelog falls through to date matching, including a +/- one-day search. An absent player or missing fact row can acquire another game's result and history. My minimal fixture supplies game 999 on July 3 and receives game 100 on July 2 while the enriched row still carries game 999.

   This also reproduces with real inputs: 16 raw 2024 closing batter-hits OVER lines are misbound by this helper. Examples include Ian Happ, requested game 746825 on September 22, receiving game 746826 on September 21; and Adley Rutschman, requested 747001 on August 16, receiving 747002 on August 15. That count is a helper-level audit, not the final count after upstream eligibility and doubleheader filtering. Reject a contradictory/missing explicit identity; an absence is not permission to borrow a neighbor's box score. Reproduction: `mlb`.

5. **[P1] NFL serving does not assemble the feature vector used in validation.** `nfl_epa.py:430-431` calls `nfl_model.predict` without `gid`; `nfl_model.py:33-38` consequently returns zero rest for every such prediction. The dataset builder supplies the game ID and includes rest. For `2024_04_CIN_CAR`, the feature builder returns margin -0.06878, while the same model with the game ID returns +0.27642: exactly the missing 0.3452-point rest term.

   Separately, `app.py:3142` slices the UTC kickoff date. `_week_for` matches the schedule's local gameday. A night game crossing UTC midnight therefore loses the current-week injury lookup and the injury-driven QB backup lookup. For `2024_04_DAL_NYG`, September 26 resolves week 4; the UTC date September 27 resolves no week. Canonicalize the game once and pass its ID, gameday, and week through both serving and validation. Reproduction: `wiring`. The NFL branch of `_predict_margin` itself is correctly sport-gated; a direct smoke test of that function cannot detect these upstream errors.

6. **[P2] The NFL totals diagnostic still has a defensive-EPA sign error.** `nfl_totals.py:92` computes `(home_off - away_def) + (away_off - home_def)`. Here `def_epa` is opponents' EPA allowed, so a higher value means a weaker defense. Subtracting it lowers expected scoring against weaker defenses and reduces the feature to the sum of team net EPA. This does not represent combined offensive production against opposing defenses.

   Replacing the two subtractions with additions, with the same games, remaining features, fitting procedure, and folds, improves pooled RMSE **13.46516 -> 13.32496**. Per-season values are 2023: 13.71591 -> 13.78603; 2024: 12.95325 -> 12.92094; 2025: 13.71199 -> 13.25363. It is not uniformly better, not an untouched new holdout, and not evidence of positive betting ROI. It is a concrete counterexample to “we exhausted the modeling avenues.” Reproduction: `totals`. This diagnostic also uses actual game weather from the PBP record, not archived forecasts available at an early betting snapshot.

7. **[P2] Candidate staging protects the live file, but its diff can hide material prop changes.** `calibration_loader.py:365-369` reports changes only when the top-level method or observation count differs. Changing residual parameters, distribution parameters, projection knobs, or per-line methods while retaining those two values produces an empty prop-change list. A fixture that changes residual mean from 0 to 100 and removes `line_methods` returns no reported changes.

   The staging/serving separation and archival promotion mechanism are useful and tested. They do not fix incumbent hysteresis: the synthetic sweep can still replace the incumbent in the candidate, and the real-line stage reads that candidate as its starting point. The advertised `--diff` review is not sufficient protection when it omits the changed fields. Compare the complete nested prop configuration, and retain/evaluate the true incumbent separately. Reproduction: `mlb`, using temporary calibration files only.

8. **[P2] The feature cache lacks the dependencies needed to preserve fit/serve parity.** `feature_store.py:26-33` versions solely by game count and maximum date. `backtest.py:1287-1328` reuses cached outputs; the NFL output now includes a fitted `nfl_pred_margin`, not just raw features. Changing weights, switching live/candidate calibration, fixing the model, or correcting fact values without changing count/latest date can therefore reuse an old prediction. No NFL feature-cache file was present on this machine, so I did not observe an already-poisoned NFL cache. The invalidation gap is in the code. Cache raw features or include code, data, feature-schema, and calibration fingerprints as applicable.

9. **[P2] The NFL props “scratch correction” confuses active zero-stat players with nonparticipants.** `nfl_props_scan.py:151-160` infers scratch status from the absence of a player-week stat row and presence in another week. `:330-344` then declares scratches automatic OVER losses. Neither inference is valid. Of the 31 dropped receptions-0.5 cases, **30 have positive recorded snaps**, and all 31 resolve to roster IDs with no receiver-target rows in that game's week in the local PBP. The remaining case, Skyy Moore in the 2023-season Super Bowl, has no snap record in the mirror; absence from a stats table alone does not establish his participation.

   Starting from the reported 169 bets at +14.7614%, adding the 30 snap-confirmed zero-reception losses gives **199 bets at -2.5393% ROI**. Counting the remaining case as a loss gives the old -3.03%; treating a verified nonparticipant as void does not create that loss. The rejection of this candidate survives, but the explanation and reusable grading rule must change. Ordinary nonparticipant props are void under the relevant participation rules, not automatically UNDER wins. See the [2024 DraftKings rules, football player props, page 52](https://massgaming.com/wp-content/uploads/DraftKings-House-Rules-5.14.24.pdf) and [DraftKings' nonparticipation explanation](https://help.draftkings.com/hc/en-us/articles/19067533170451-How-to-bet-on-Football-US). Historical grading must apply the relevant book/market/date rules. Reproduction: `props`.

10. **[P2] The supposedly non-QB injury feature includes quarterbacks.** `nfl_injury_impact.py:164` accepts any player with sufficient offensive snap share, including `position == 'QB'`. Its EPA sum also contains passing EPA. I found 20 qualifying QB team-week entries in 2024; Brock Purdy in week 12 contributes 68.6966 absolute EPA to the “offensive skill” burden. That overlaps the separate QB feature and invalidates the stated interpretation of the injury lift. Exclude QBs explicitly, then re-fit; do not remove the feature at serving time while retaining weights fitted with it. Reproduction: `wiring`.

11. **[P2] The required-edge diagnostic does not evaluate the shipped model or its served probabilities.** `nfl_edge_calibration.py:36` selects the old four-feature `base+QB+inj` model. It omits the shipped home-field intercept and rest term. It also uses raw Normal probabilities while the app subsequently applies NFL shrink factors (moneyline 0.65, spreads 0.10). Calling its output the curve for “app-computed edge” is inaccurate. `nfl_injury_edge.py` and `nfl_qb_edge.py` are useful nested-feature experiments, but likewise do not certify the final six-feature app pipeline. Re-run edge buckets using exactly the frozen serving model and executable offers.

12. **[P2] “OOS” is being used more broadly than the evaluation supports.** `nfl_model.py:119` trains on every season except the held-out one. Thus 2023 predictions use coefficients fitted on 2024-25, and 2024 predictions use 2025. This is out-of-row/season validation under an exchangeability assumption; it is not a historical trading simulation in which everything was known strictly before the bet. It also does not protect against choosing among many variants after inspecting these same folds. Only the 2025 fold has a strictly earlier coefficient-training window, and that fold has already informed design decisions.

   Coverage is narrower than “three seasons of NFL”: the model's 768 games are weeks 2-18 only, with all 48 first-week games and every playoff excluded (`nfl_injury_edge.py:71`). The odds loaders additionally interpret requested seasons as calendar years, dropping the last requested NFL season's following-January quotes. Reading the existing 2026 calendar file recovers 14 additional games with both moneyline and spread in my paired comparison. Use NFL-season membership for eligibility and read all calendar partitions it spans. Reproduction: `nfl` and `benchmark`.

**What the numerical checks actually support**

The dedicated fit exactly reproduced the committed rounded coefficients and sigma: HFA 2.1278, EPA 32.5206, QB 10.8797, offensive injuries 0.0652, defensive injuries 0.6489, rest 0.3452, sigma 13.123. The CLI prints OOS RMSE 13.185. It averages per-fold RMSE; the proper pooled RMSE is 13.18545 here, an immaterial difference. The PBP final margins matched the schedule on all 768 modeled games.

The following are paired comparisons of the same games. Model coefficients are fitted by the existing LOSO procedure; probability conversion uses residual sigma fitted within each training fold. Consequently these results retain the QB-identity and temporal-validation qualifications above. They are benchmark sensitivity checks, not a replacement prospective validation.

The model also loses on the original-window games with absolute probability disagreement over 15 points: n=87, Brier 0.25389 versus market 0.16389. These are not exactly the handoff's quoted conditional numbers because this reconstruction fixes the scoring recipe explicitly. The direction is the same. The close is a strong empirical reference; the code prices DraftKings, so calling it a separately verified sharp-book consensus would be inaccurate. The `fair_two_way` path uses the shared power-devig implementation; I found no sign reversal there, and its tests pass.

The data does **not** prove that 13 points of residual noise, or a 0.5-RMSE deficit to the market, is irreducible from the available inputs. It measures the errors of particular estimators. Likewise, Brier around 0.24-0.25 is not proof of a variance floor: 0.25 is the score of a constant 50% forecast. A ceiling requires a much stronger argument than unsuccessful feature variants. Seven related experiments on reused folds are neither seven independent replications nor an exhaustive search. Failed significance is also not an equivalence test. The appropriate statement is “the tested approaches have not produced a reliable incremental signal or executable edge.”
