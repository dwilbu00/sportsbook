# SUBSYSTEM
Caching, per-rerun cost, and per-game state (MLB props model): Streamlit @st.cache_data (app.py only), the mlb_starters/espn_cache file-JSON disk caches, module-level in-process memo dicts, game_results._SCORE_CACHE completeness/TTL pattern, db_store SQL engine singleton + durable statcast_asof/gamelog tables, and the button-gated + session_state-frozen analysis flow where matchup_features is built once per game and threaded into both team analyzers and analyze_player_props_value.

## FUNCTIONS
- **build_matchup_features** (mlb_starters.py:867-1013)
  The existing per-game feature producer, built once per game at app.py:2619. Resolves both starters+quality, opposing-lineup offense-vs-hand, bullpens, scalar starter_edge (tanh), and the expected_runs factor block. The natural GameContext PRODUCER to extend/wrap — it already does all the per-game network I/O.
- **analyze_player_props_value** (props.py:862-866 (sig))
  Per-game props entry point: signature (prop_data, player_histories, threshold_pct=5.0, sport_key=None, team_defense=None, espn_teams=None, safe_mode=False, safe_target=0.95, team_schedules=None, matchup_features=None, weather=None). Loops every prop x every player for ONE game. Has home/away names (949-950) + commence_iso (902). The GameContext CONSUMER seam: add a game_context kwarg, build/accept once here, share across all batters.
- **_distributional_over_rate** (props.py:471-529)
  Per-batter binomial P(over) for batter_hits: computes r_emp (weighted hits/AB) + expected_ab from the player's games, pulls xBA/hard-hit/barrel from statcast_asof, calls _dist_p_over. The exact point a GameContext-reconciled per-AB rate / expected-AB / shared game-total tilt would enter.
- **_dist_p_over** (props.py:424-468)
  Pure analytic binomial: p_AB = clamp(level*quality_adj*rate_mult), n=round(expected_ab*exposure_mult), P(over)=hits_at_least(int(line)+1,n,p_AB). Shared with offline book_line_calibration.project_distributional. Where a bottom-up reconciled p_AB/n would be substituted.
- **_mlb_prop_matchup_mult** (props.py:93-162)
  Bounded per-prop projection multiplier (log5 batter-vs-starter / pitcher-vs-lineup) from matchup_features; clamped [0.7,1.4]. Current (scalar, per-player, non-joint) way matchup flows into a batter prop — would be subsumed by a joint GameContext rate.
- **analyze_totals_value** (analysis.py:341-402/457-460)
  Team game-total path: projected_total (mean, L402) + total_std (_weighted_std, L457) + Normal over-rate 1-_norm_cdf(z) (L459). The existing analytic game-total distribution GameContext must stay consistent with.
- **_mlb_expected_runs_projection** (analysis.py:136-192)
  Turns matchup_features['expected_runs'] factors into home_runs/away_runs (via expected_runs_from_factors) + margin/spread shares. The per-side team-run means a GameContext would center on. Caches challenger cfg in module-level _EXPECTED_RUNS_CACHE.
- **expected_runs_from_factors** (mlb_starters.py:350-375)
  base_runs * offense_factor^ow / staff_suppression^pw, bounded [0.5,12]. Analytic per-side expected-runs kernel — the mean input to a moment-matched team-run distribution.
- **poisson_margin_probability** (mlb_starters.py:393-424)
  Builds per-team Poisson run PMFs (O(max_runs)) and convolves for P(margin). Stdlib analytic joint-of-two-teams already in repo; the PMF-build pattern is directly reusable for a game-total / team-hits distribution.
- **negative_binomial_margin_probability** (mlb_starters.py:427-472)
  Overdispersed (var=mean+phi*mean^2) run PMFs + convolution; phi=0 falls back to Poisson. Reusable analytic kernel for a moment-matched overdispersed team-run/total distribution (no MC).
- **get_confirmed_lineup / lineup_player_context** (mlb_starters.py:541-559 / 603-611)
  Confirmed batting order (short TTL disk cache, 5-min area) and per-player batting_order lookup. The set of batters + slot exposure needed to distribute team hits across the lineup for bottom-up reconciliation.
- **hits_at_least / negbin_at_least** (stats.py:152-180 / 183-221)
  Pure-stdlib binomial and NegBin/Poisson survival P(X>=k) via ratio recurrence (no factorials/scipy). The per-batter and per-count distribution evaluators a joint model reuses.
- **_norm_cdf / _norm_ppf / _normal_inv_cdf** (stats.py:14-16 / 19-54 / 292-327)
  erf-based standard-normal CDF and Acklam probit. The moment-matching-to-Normal primitives (mean+var -> tail prob) for an analytic game-total distribution.
- **fit_negbin_dispersion / _weighted_mean / _weighted_std** (stats.py:245-289 / 96-103 / 134-149)
  MoM+bounded-MLE dispersion fit and weighted moments — the moment estimators for fitting a per-game distribution's mean/variance analytically.
- **_read_cache / _write_cache** (mlb_starters.py:105-122)
  File JSON disk cache: key md5(name)->cache/mlb_<hash>.json, envelope {cached_at,data}, per-call max_age TTL. Backs every build_matchup_features fetch. EPHEMERAL on Streamlit Cloud.
- **load_config / fetch_events / fetch_espn_teams / _cached_* ** (app.py:713-884)
  The only @st.cache_data users (ttl 60-3600, keyed by args). NONE cover the projection/matchup path — model recompute is button-gated + session_state-frozen instead.
- **_SCORE_CACHE (grading slate memo)** (game_results.py:37-40)
  In-process dict keyed by date with a completeness-OR-TTL guard (immutable once every game terminal, else 20-min TTL). The best in-repo TEMPLATE for a per-game GameContext memo that must not pin a stale lineup/starter.
- **get_engine / enabled (db_store)** (db_store.py:506-508 / 541-567)
  Process-singleton SQLAlchemy Engine + SQL feature flag. Durable per-player state (statcast_asof, gamelog_store) is read per-call via indexed SELECT, not in-process memoized beyond the engine.

## DATA_FLOW
ENTRY (Streamlit button, app.py:2414 `if analyze_clicked and selected_game_labels:`). ALL model work is gated behind this button — a plain rerun (filter toggle, bet selection, alt-line fetch) does NOT re-run it; it reads the frozen `st.session_state["analysis_results"]` written at app.py:2781. So "per-rerun cost" for the model is ~0; the real cost unit is one Analyze click.

Within one Analyze: Phase 1 fans out odds+ESPN fetches in a ThreadPoolExecutor(max_workers=20) (app.py:2453); Phase 2 parses props + fires player-history futures (2558); Phase 3 (app.py:2597 `for event in selected_events:`) is CPU-only and builds, PER GAME, `matchup_features = mlb_starters.build_matchup_features(home, away, game_date, season)` (app.py:2619) plus `confirmed_lineup` (2624) and `probable_starters` (2632). That one `matchup_features` dict is threaded into BOTH the team analyzers (analyze_moneyline/spreads/totals_value, app.py:2708-2712) AND `analyze_player_props_value(...)` (app.py:2740). Results accumulate into all_ml/all_spreads/all_totals/all_props and are stored in session_state (2781).

KEY DICT SHAPES:
matchup_features (mlb_starters.build_matchup_features return, mlb_starters.py:867-1013): {"home": {"starter": {run_suppression, xba, k_pct, avg_ip, throws, bf, xwoba}, "opp_offense_vs_hand": {ops, k_pct,...}, "bullpen": {bullpen_suppression, bullpen_xwoba}}, "away": {...}, "starter_edge": float in ~[-1,1] via tanh, "expected_runs": {"complete": bool, "home_offense_factor", "away_offense_factor", "home_staff_suppression", "away_staff_suppression"}}. All pieces degrade to None independently.

Per-batter projection (props.py analyze loop 968-1319): base_proj = _weighted_mean(values, weights) with recency + venue + opp-defense weights; then multiplied by combined_mult = output_def_mult*matchup_mult*lineup_mult*park_mult*weather_mult*rest_mult (props.py:1251). For batter_hits method "D": _distributional_over_rate → _dist_p_over builds p_AB (per-AB hit prob from level=(1-s)·r_emp+s·xBA, quality_adj, rate_mult) and n=round(expected_ab·exposure_mult), then P(over)=stats.hits_at_least(int(line)+1, n, p_AB). EXIT: candidate dicts with over_rate/edge/is_value.

Team-total path (analysis.analyze_totals_value:341): projected_total (L402) shifted by starter/bullpen (L423), spread total_std = _weighted_std(historical_totals) (L457), model_over_hit_rate = 1 - _norm_cdf((line-projected_total)/total_std) (L459). Expected team runs (analysis._mlb_expected_runs_projection:136 → mlb_starters.expected_runs_from_factors) feed poisson/negbin_margin_probability for spreads/ML.

## GAMECONTEXT_RELEVANCE
TODAY there is NO per-game GameContext and NO shared run/pace/total distribution. The per-game object that exists is `matchup_features` (mlb_starters.build_matchup_features), which already resolves — once per game — both probable starters + quality, both opposing lineups' offense-vs-hand, both bullpens, a scalar starter_edge, and an `expected_runs` block of home/away offense & staff FACTORS (multiplicative, centered on 1.0). It is threaded to team markets AND props but each consumer independently turns it into its own number: totals derives a scalar projected_total + Normal std (analysis.py:402/457); spreads/ML derive home_runs/away_runs then Poisson/NegBin margin probs (mlb_starters.py:393/427); props derive a bounded per-prop multiplier (_mlb_prop_matchup_mult, props.py:93). NONE of these share a joint distribution and NOTHING reconciles bottom-up: batter hits are priced fully independently per player (props.py:471 _distributional_over_rate uses each batter's own r_emp·xBA·AB with no team-hits/team-runs/game-total constraint). 

WHAT'S MISSING for 3.1: (1) a single per-game producer that emits a SHARED team-run mean per side and a game-total distribution consistent with what analyze_totals_value/_mlb_expected_runs_projection already compute; (2) a lineup→batter allocation (from get_confirmed_lineup / batting-order exposure) so team hits distribute across batters; (3) a reconciliation step so Σ batter-hit means ↔ team hits ↔ team runs ↔ game total; (4) an analytic moment-matched joint (Poisson/NegBin/Normal via existing helpers) built ONCE per game and consumed by the per-batter binomial in _dist_p_over. The raw run/factor machinery (expected_runs_from_factors, poisson/negbin PMFs, projected_total/std) already exists — 3.1 must UNIFY it into one cached GameContext instead of three parallel derivations.

## RISKS
- LEAKAGE: every as-of input must respect the strict cutoff. statcast_asof rows are built with as_of < day-after-end (statcast_asof.py:177); find_player_id/get_rates are season-to-date; the only runtime time anchor is commence_iso (props.py:902) / game_date (app.py:2610-2615). A GameContext must derive its cutoff from commence_iso and must NOT pull the current game or future games into team-run/hit means.
- PER-ANALYZE COST (not per-rerun): analyze_player_props_value loops every player; the batter_hits path ALREADY calls find_player_id + statcast_asof.get_rates PER PLAYER TWICE (props.py:1146+1150 and 514+516). A GameContext must be built ONCE per game and cache the lineup-wide player_id/xBA/rate lookups + the team-run/total distribution, or it multiplies StatsAPI + Azure-SQL round-trips by the roster size.
- NO MONTE-CARLO (hard requirement + repo invariant): there is zero MC anywhere in the pricing path today — everything is closed-form (Poisson/NegBin PMF convolution O(max_runs^2)~900 ops, binomial/negbin survival O(k), Normal via erf). The joint model must moment-match analytically using these; introducing per-rerun simulation would violate the design and the button-gated/session_state cost model.
- RERUN COST GUARD: analysis is gated behind `if analyze_clicked` (app.py:2414) and frozen into st.session_state['analysis_results'] (2781); a plain rerun never recomputes. Build GameContext INSIDE that block (or in analyze_player_props_value which only runs there) — never at module import or top-level script body, or it will run on every rerun.
- STALE-STATE ON A PROCESS MEMO: if GameContext is memoized in a process-level dict (game_results._SCORE_CACHE pattern, game_results.py:37), it MUST carry a completeness/TTL guard — probable starters (get_probable_starters, 5-min TTL) and confirmed lineups (get_confirmed_lineup, short TTL) CHANGE during the day; a naive infinite memo would pin a wrong starter/lineup and mis-price every batter for that game.
- EPHEMERAL DISK CACHE: mlb_starters _read_cache/_write_cache (cache/mlb_*.json) and espn_cache are file-based and NOT durable on Streamlit Cloud — a GameContext built from them recomputes cold after each redeploy/restart. Only SQL (statcast_asof, gamelog_store, db_store engine) is durable; lean on it for the stable inputs.
- COUPLING / DOUBLE-I/O: build_matchup_features already performs the heavy per-game network I/O (probables, pitcher quality, offense splits, bullpen, get_expected_runs_team_factors, savant). Reuse its output as the GameContext producer input; building a parallel producer would double the fetches AND risk the joint distribution diverging from the totals/spreads path that reads the same matchup_features.
- FAIL-OPEN + BACKWARD COMPAT: matchup_features and every multiplier already degrade to None/1.0 (props.py:107, analysis.py:409). The new game_context kwarg must default to None and no-op for non-MLB and on any missing piece, so the ~800-test suite and non-MLB sports stay byte-identical (analysis re-exports props/stats/pricing_common names — a signature change ripples through the compat surface).
- DOUBLE-COUNTING: batter_hits already blends toward xBA in TWO places — the mean blend (_xstats_blend, props.py:1159) and the distributional level (_dist_p_over level term, props.py:440). _distributional_over_rate deliberately rebuilds from raw hits/AB (NOT base_proj) to avoid double-counting (props.py:488-489). A GameContext reconciliation that also tilts the per-AB rate must not re-apply matchup/xBA effects already in rate_mult/level, or it triple-counts.
- STDLIB-ONLY: no numpy/scipy/pandas in any pricing path (stats.py/mlb_starters.py import only `math`+stdlib). The joint model must stay pure-Python; all needed primitives (erf CDF, probit, binomial/negbin survival, PMF convolution, dispersion MLE, weighted moments) already exist in stats.py + mlb_starters.py.
