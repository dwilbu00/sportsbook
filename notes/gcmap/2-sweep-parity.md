# SUBSYSTEM
Synthetic sweep + three-way projection-parity (offline real-line / synthetic sweep / runtime) that every player-prop feature must maintain, and the prop_features shared helper that prevents drift.

## FUNCTIONS
- **prop_features.projection_multiplier** (prop_features.py:144-161)
  THE shared multiplier. Combined bounded multiplier over all registered features that apply to prop_key at {name: strength}; returns 1.0 (no-op) when empty. Signature: projection_multiplier(prop_key, feature_strengths, prior_game_dates, graded_date). Called identically by all three paths.
- **prop_features.strengths_from_params** (prop_features.py:125-141)
  Extracts {feature_name: strength} from a params/cfg dict by reading each feature's runtime_knob plus an explicit params['features'] override map. All three paths call this to derive feat_strengths before projection_multiplier.
- **prop_features.FEATURE_REGISTRY / _rest_fn / rest_multiplier** (prop_features.py:104-112, 94-96, 67-91)
  Plain-data registry (one tenant: 'rest', props={pitcher_outs,pitcher_strikeouts,batter_hits}, strengths=(0.0,0.5,1.0), runtime_knob='rest_strength'). rest_multiplier is leakage-safe (only prior dates strictly < graded_date), bounded tanh of rest-vs-own-cadence.
- **props.analyze_player_props_value** (props.py:862-866 (def); apply 1245-1259)
  RUNTIME path. Builds rest_mult via prop_features.projection_multiplier (1246-1249), folds it into combined_mult = output_def_mult*matchup_mult*lineup_mult*park_mult*weather_mult*rest_mult (1251-1252), avg_stat = base_proj*combined_mult (1254), effective_line = line/combined_mult (1258). Sig includes matchup_features=None, weather=None.
- **props._mlb_prop_matchup_mult** (props.py:93-162)
  RUNTIME-ONLY starter/opponent matchup multiplier (log5 batter-vs-starter, lineup-vs-pitcher). Fed matchup_features at props.py:1200. CRITICAL: has NO parity partner in the offline or sweep paths — it is validated separately (backtest_props.py), NOT through the three-way prop_features parity.
- **backtest.run_player_props_backtest** (backtest.py:2329-2334 (def); feature apply 2652-2714)
  SYNTHETIC SWEEP path. Per-PLAYER (fetch_player_data at 2349), per-prop, per-test-game. feat_strengths=strengths_from_params(params) (2662); projected*=feat_mult (2671); in calib_obs block line_eff = synthetic_line/feat_mult (2706-2707) so method A shifts the line while B/C/E use the raw synthetic_line target. Emits calib_obs tuple (name, projected, synthetic_line, actual, empirical_over, upcoming_date) at 2712-2714.
- **book_line_calibration.project_and_empirical** (book_line_calibration.py:482-484 (def); feature apply 591-610)
  OFFLINE REAL-LINE path. Reconstructs the runtime projection at the BOOK line. feat_strengths=strengths_from_params(params) (598); projected*=feat_mult (605); line_eff = line/feat_mult (606); empirical_over at feature-shifted line (609). Mirrors props.py combined_mult so re-fit residuals match production.
- **backtest._build_props_sweep_grid** (backtest.py:1946-2001)
  Enumerates the 6-axis cross-product (half_life[None,5,10,15] x opp_defense[0,.5,1] x def_adj[0,.5,1] x shrink_k[0,5,10,15] x venue[0,.25] x rest[0,1]) = 576 variants. Name = f'{hl_label}/opp{opp}/defadj{da}/shrink{sk}/ven{vs}/rest{rs}' (1995-1996). rest is INNERMOST loop so its rest0.0/rest1.0 twins are adjacent for first-seen tie-break.
- **backtest._preset** (backtest.py:1858-1881)
  Turns knob kwargs into the params dict the three projection paths read. Any new sweepable knob/feature must add a kwarg + dict key here (rest_strength added at 1862/1877).
- **refit_calibration._parse_variant_name** (refit_calibration.py:274-337)
  Parses a /token{v} sweep name back into {half_life, opp_defense_strength, output_def_strength, shrink_k, venue_strength, rest_strength}. Accepts 3/5/6-part legacy formats; the 6th /rest<r> token is trimmed then reused (296-305). Adding an axis = extend this parser.
- **refit_calibration._build_prop_cfg** (refit_calibration.py:535-571)
  PERSISTENCE. Combines the winning variant's parsed params + fitted residuals into the calibration/<sport>.json entry (writes rest_strength at 556). props.py reads these back via _knob. A new axis must be added to this cfg dict to survive from sweep→runtime.
- **refit_calibration._best_per_prop / _variant_confirms** (refit_calibration.py:472-532, 447-469)
  The confirmation gate: per prop, picks lowest-Brier (variant x method) that beats the all-off baseline variant out-of-sample in BOTH chronological folds (strict '<' first-seen tie-break at 518). This is what auto-adopts a sweep axis. Runs on calib_obs from run_player_props_backtest.
- **backtest.run_odds_backtest team loop** (backtest.py:1146-1216 (matchup_features at 1189))
  TEAM-level (moneyline/spread/total) backtest loop — SEPARATE from the props backtest. Per game it has date, home/away, home_prior/away_prior (prior_games_for, 1160-1161), matchup_features via _matchup_features_for (1189), actual_margin, actual_total (1167-1168), and the book total line. This is the only loop with per-game run-total context.
- **backtest._matchup_features_for / _mlb_matchup_features** (backtest.py:1033-1040, 997-1013)
  Backtest-side builder that calls mlb_starters.build_matchup_features(home, away, date, season) for a game. Only invoked in the team loop (1189), never in run_player_props_backtest.
- **mlb_starters.build_matchup_features** (mlb_starters.py:867-1013)
  Per-game feature bundle shared by team markets AND props. Produces result['home'/'away'] (starter, opp_offense_vs_hand, bullpen), starter_edge (954), and result['expected_runs'] = {complete, home/away_offense_factor, home/away_staff_suppression} (1004-1011). Sig: build_matchup_features(home_team, away_team, date, season, team_index=None).
- **mlb_starters.expected_runs_from_factors** (mlb_starters.py:350-375)
  Analytic per-side expected runs: base_runs * offense_factor^offense_weight / staff_suppression^pitching_weight, clamped [0.5,12.0]. Stdlib-only. The existing per-game run-total kernel a GameContext would build on.
- **analysis._mlb_expected_runs_projection** (analysis.py:136-192)
  Turns matchup_features['expected_runs'] into {home_runs, away_runs, margin, spread_share, margin_share} using the committed challenger config. Currently gated to SPREADS only (live_markets.spreads, 155); NOT shared with props or totals mean.
- **analysis.analyze_totals_value** (analysis.py:341-424)
  RUNTIME team total. projected_total = (offense+defense)/2 (400-402) + starter_total_shift from matchup_features run_suppression/bullpen excess (408-424). The existing per-game total mean — but computed independently of props and of expected_runs_from_factors.

## DATA_FLOW
app.py builds matchup_features ONCE per game (app.py:2619, mlb_starters.build_matchup_features) and threads the SAME object into both team markets (analyze_totals_value/moneyline/spreads, app.py:2708-2712) and props (analyze_player_props_value, app.py:2747). This once-per-game build+share is the natural GameContext seam. \n\nThree projection paths each take a `params`/cfg dict and derive feat_strengths via prop_features.strengths_from_params, then multiply the projection and divide the line by prop_features.projection_multiplier — keeping A (empirical over-rate at the shifted line) and B/C/E (residual/distributional on the scaled projection) consistent: (1) RUNTIME props.py combined_mult (1251) / effective_line (1258); (2) SWEEP backtest.py projected*=feat_mult (2671) and calib_obs line_eff (2706); (3) OFFLINE book_line_calibration projected*=feat_mult (605) / line_eff (606). \n\nSweep→ship pipeline: _build_props_sweep_grid (576 variants, /token{v} names) → run_player_props_backtest emits calib_obs tuples (name, projected, synthetic_line, actual, empirical_over, upcoming_date) per variant×prop → _best_per_prop + _variant_confirms 2-fold gate picks a winner → _build_prop_cfg persists parsed knobs + fitted residuals into calibration/<sport>.json → props.py _knob reads them back at runtime. \n\nKey object shapes: params/_preset dict has keys half_life, venue_strength, opp_defense_strength, def_adj, shrink_k, def_window, park_strength, rest_strength (backtest.py:1863-1881). matchup_features = {home:{starter,opp_offense_vs_hand,bullpen}, away:{...}, starter_edge:float, expected_runs:{complete:bool, home_offense_factor, away_offense_factor, home_staff_suppression, away_staff_suppression}}. Offline real-line obs = {player, prop_key, game_date, line, test_game, prior_games, stat_label} (book_line_calibration.py:448-449, 500-503) — per-player-game, NO opposing-team fields. calib_obs residual basis: _fit_residuals reads index[1]=projected, index[3]=actual (refit_calibration.py:342).

## GAMECONTEXT_RELEVANCE
CURRENTLY: a per-game team run total exists only at the TEAM level and only at runtime. analyze_totals_value (analysis.py:400-424) computes a total mean = (offense+defense)/2 + starter shift; separately _mlb_expected_runs_projection (analysis.py:136) produces home_runs/away_runs/margin from matchup_features['expected_runs'] via expected_runs_from_factors (mlb_starters.py:350) but is gated to SPREADS only and never reaches props. There is NO GameContext / game_context / shared run_total / team_total / joint-model object anywhere (grep confirms zero hits). \n\nBatter aggregation: NONE. props.py analyzes each player independently; _mlb_prop_matchup_mult (props.py:93) nudges each batter by the opposing starter in isolation with no sum-of-batter-hits <-> team-hits <-> team-runs <-> game-total reconciliation. pace is not modeled for MLB props at all. \n\nMISSING for a per-game joint GameContext: (1) a shared per-game run/pace/total object consumed by props (only matchup_features is shared today, and its expected_runs is spreads-only); (2) an analytic moment-matching total distribution (only expected_runs_from_factors point estimates + the team-total historical spread in analyze_totals_value exist — the NegBin/Poisson moment code from method 'E' is the stdlib kernel to reuse); (3) bottom-up reconciliation of batter hits→team hits→team runs; (4) a per-game cache; and CRITICALLY (5) the props validation harness (run_player_props_backtest) and the offline real-line harness are per-PLAYER and structurally lack opposing-team / run-total context, so a GameContext signal cannot ride the existing three-way parity without reworking those loops (see integration_seams/risks).

## INTEGRATION_SEAMS
- PRODUCE (runtime, primary seam): app.py:2619 — build_matchup_features is already called once per game and shared to team+props. A GameContext would be built here (or inside analyze_player_props_value once per prop_data['home_team']/['away_team']) and cached per game; expected_runs (mlb_starters.py:1004-1011) + expected_runs_from_factors (mlb_starters.py:350) are the ready analytic run-total inputs.
- CONSUME (runtime): props.py:1251 combined_mult and props.py:1258 effective_line — a batter reconciliation multiplier (sum-of-batters vs team-runs) slots here beside rest_mult/matchup_mult; analyze_player_props_value signature props.py:862-866 must gain a game_context (or reuse matchup_features) param. Team consumer: analysis.py:400-424 (analyze_totals_value) and analysis.py:136 (_mlb_expected_runs_projection) are where the SAME GameContext total would feed the team total for internal consistency.
- SHARED HELPER (parity): prop_features.projection_multiplier (prop_features.py:144) + FEATURE_REGISTRY (prop_features.py:104) + strengths_from_params (prop_features.py:125) — the only drift-proof way to add a GameContext-derived multiplier is to register it here so all three paths pick it up identically; feature_applies (prop_features.py:117) restricts it to batter props.
- OFFLINE REAL-LINE (validation): book_line_calibration.project_and_empirical (book_line_calibration.py:482, feature block 598-606) — mirrors runtime; but its obs (book_line_calibration.py:448) carry no opposing-team fields, so a GameContext here needs the opponent/starter joined in at harvest time.
- SYNTHETIC SWEEP (validation): backtest.run_player_props_backtest (backtest.py:2329, feature block 2652-2714) — per-player loop with NO matchup_features and NO per-game run total; a GameContext axis requires either threading opponent/run-total context into this loop or a new game-oriented backtest built on the team loop.
- PERSISTENCE (sweep→ship): backtest._build_props_sweep_grid (backtest.py:1946, name at 1995) + backtest._preset (backtest.py:1858) + refit_calibration._parse_variant_name (refit_calibration.py:274) + refit_calibration._build_prop_cfg (refit_calibration.py:535, e.g. rest_strength persisted at 556) + props.py _knob read (props.py:965) — the full chain any new strength knob must be added to.
- RUN-TOTAL CONTEXT ALREADY AVAILABLE OFFLINE: backtest.py:1189 team loop (_matchup_features_for → build_matchup_features) with home_prior/away_prior, actual_total (1168), and the book total line — the only offline place a GameContext run total can be built/validated WITHOUT new fetches, but it is disjoint from the props backtest.

## RISKS
- PARITY GAP (biggest): _mlb_prop_matchup_mult (props.py:93/1200) already lives in combined_mult with NO offline or sweep partner — it is validated only via backtest_props.py. A GameContext batter multiplier is matchup-shaped, so it will face the same problem: run_player_props_backtest (backtest.py:2329) and project_and_empirical (book_line_calibration.py:482) are per-player and have no opposing-team/run-total context. Either rework both to a game-oriented join, or validate GameContext separately (like matchup_mult) and accept it bypasses the three-way prop_features parity.
- LEAKAGE: every existing feature uses strictly-before-game_date data (prop_features 82-83; _resolve_opp_pa_asof; as-of xBA index). expected_runs uses get_expected_runs_team_factors(season, as_of) (mlb_starters.py:194) which honors as_of at runtime, but the team backtest must pass the game date as as_of; a GameContext total must be built as-of or it leaks future team results into batter calibration.
- PER-RERUN COST / CACHING: matchup_features/expected_runs pull Savant + StatsAPI (build_matchup_features 883-1011, get_expected_runs_team_factors network) and are rebuilt each app pass at app.py:2619 with no explicit Streamlit cache seen; the 3.1 mandate (analytic moment-matching, cache per game, NO per-rerun Monte-Carlo) requires memoizing the GameContext per (home,away,date) and using expected_runs_from_factors-style closed-form moments, not sampling.
- STDLIB-ONLY: no numpy/scipy — the total/run distribution and its moment-matching (and any batter-sum reconciliation) must be hand-rolled; reuse the existing NegBin/Poisson moment code (method 'E', test_negbin.py) and expected_runs_from_factors rather than importing.
- TIE-BREAK / OFF-CELL INVARIANT: _build_props_sweep_grid orders the candidate axis innermost so its off-cell is byte-identical to baseline and _best_per_prop's strict '<' first-seen (refit_calibration.py:518) can never persist the knob where it doesn't strictly win (prop_features.py:1971-1978 documents this). Any GameContext axis must preserve strength-0 == production bit-for-bit and this ordering, or it regresses excluded props.
- COUPLING / DOUBLE-COUNTING: a shared GameContext run total would feed BOTH analyze_totals_value (analysis.py:400) and props; it must not double-apply the existing starter_total_shift (analysis.py:423) or the per-batter _mlb_prop_matchup_mult (props.py:161) — reconciliation has to replace, not stack on, those independent adjustments.
- PERSISTENCE COMPLETENESS: forgetting any link in _preset→grid-name→_parse_variant_name→_build_prop_cfg→props _knob makes a swept GameContext knob a silent no-op at runtime (the exact P2.1 trap the code comments warn about at backtest.py:1953-1955); calibration state is SQL/JSON durable so a half-wired knob ships a validated-but-inert config.
