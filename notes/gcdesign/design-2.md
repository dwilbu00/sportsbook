## approach_name
Design C — "Shared-Environment Reconciliation, Phased" (GameContext v1 = a gate-shipped per-batter run-environment scalar; v2 = the full run→hits→batter distribution; v3 = shared-run correlation)

## one_line_thesis
Ship the bottom-up reconciliation as its degenerate shared-scalar case FIRST — a per-batter mean multiplier r derived from the opponent's leakage-safe as-of team-staff xwOBA, ridden through the existing prop_features feat_mult seam so the confirmation gate accepts/rejects/sizes it exactly like rest — then progressively enrich the same cached GameContext with the run pmf (tail-shape, method-axis validated) and the shared-run correlation (parlay/CLV validated).

## scope_summary
BUILT: (Phase 0) a `game_context.py` module + a leakage-safe as-of team-staff-xwOBA helper on the expected-runs path, plus refactoring mlb_starters' Poisson/NegBin `probabilities()` to RETURN the run pmf instead of discarding it (behavior-preserving). (Phase 1, gate-gated) a new `recon` feature in the prop_features registry whose per-batter multiplier is the shared team-run-environment ratio r = (opp_staff_xwoba/league)^pitching_weight, attached onto the per-player offline obs + synthetic-sweep rows via a per-(opponent,date) as-of index, plumbed into runtime combined_mult where it REPLACES matchup_mult for batter_hits. (Phase 2, method/backtest_props validated) full GameContext: run pmf → affine team-hits map → per-batter binomial with the λ reconciliation closure, exposed as a distributional method on the method axis. (Phase 3, parlay/CLV validated) same-team batter_hits correlation from the shared run pmf into parlay._pair_correlation. NOT BUILT in the shippable path: unifying analysis.py's three run estimates (totals/spread/batter) under one pmf — enabled by GameContext but deferred to Phase 4; no Monte-Carlo anywhere; no change to pitcher props' matchup path; no season-to-date leaky sources in any validation fold.

## gamecontext_object
Shape (new module game_context.py, dataclass-free plain dict for stdlib/cache friendliness): `{game_key:(home,away,date_iso), season, run_mean:{home,away}|None, staff_suppression:{home,away}|None (opponent-facing team-level, as-of xwOBA), dispersion:float (from expected_runs_challenger config / stats.fit_negbin_dispersion), source:"expected_runs_xwoba" (leakage tag asserted by validation), completeness:{run_mean:bool,staff:bool,lineup:bool}, built_at:epoch}`. Phase-2 lazily-added fields: `run_pmf:{home:[p0..p30],away:[...]}`, `team_hits_mean:{home,away}`, `lineup:<get_confirmed_lineup result, ordered>`, `per_batter:{player_key:{base_projection,expected_exposure,batting_order,share,allocated_mean}}`. BUILT once per game by `game_context.build(home,away,date,season)`: run_mean/staff via mlb_starters.expected_runs_from_factors fed get_expected_runs_team_factors (the ONLY as-of-safe path, cutoff=as_of-1d, mlb_starters.py:203); staff_suppression via a NEW `get_asof_team_staff_suppression(team,date,season)` that extends get_expected_runs_team_factors with one more Savant team query (all-pitchers team xwOBA-allowed, disk-cached 24h) so it is leakage-safe and identical in all three paths. CACHED in a module-level `_GC_CACHE` keyed (home,away,date) mirroring game_results._SCORE_CACHE (:37): completeness-not-calendar immutability, TTL split _LIVE_TTL≈20min while probable/lineup incomplete vs _FINAL_TTL≈24h once complete, so a stale probable-starter/lineup can never pin a mispriced game. At runtime it is built at app.py:2619 right beside build_matchup_features and threaded on the SAME matchup_features/session-state freeze (app.py:2781) — cost unit stays one Analyze click, ~0 per rerun. LEAKAGE: build() refuses any season-to-date source (get_team_offense_splits/get_team_bullpen_quality/get_pitcher_quality are banned inside build); source tag must equal "expected_runs_xwoba" or the completeness guard marks it incomplete → fail-open 1.0. Lineup-wide player_id/xBA/rate lookups memoized once in per_batter (today done per-player twice, props.py path).

## math
Analytic pipeline, no MC. (1) Run means: μ_home,μ_away = mlb_starters.expected_runs_from_factors(base, own_offense_factor, opp_staff_suppression, off_w, pitch_w) (mlb_starters.py:350), leakage-safe xwOBA factors. (2) Team-run dist (Phase 2 only): reuse the inner `probabilities(expected)` of mlb_starters.negative_binomial_margin_probability (:451-463) — refactor it to RETURN the 0..30 pmf list (currently convolved to a spread scalar and discarded) with variance=mean+dispersion*mean^2. (3) Team-run→team-hits map: affine through-league-constants TH = b·μ_team with b=league_H_per_gm/league_R_per_gm (≈8.5/4.5≈1.9), or an offline-fit a+bμ; team-hits treated as its own NegBin(TH, disp_H) for tails. (4) Per-batter allocation: batter share s_b = base_projection_b / Σ_j base_projection_j over the confirmed lineup (base_projection_b = recency mean, expected_exposure_b = weighted AB/game, props.py:1187/133); allocated_mean_b = s_b·TH. (5) Reconciliation closure: λ = TH / Σ_b(n_b·p_b) where n_b=expected_exposure_b, p_b=base_rate_b (props.py:133); reconciled per-AB rate = p_b·λ, so Σ n_b(p_b·λ)=TH exactly — this is the bottom-up↔top-down identity. PHASE-1 COLLAPSE: because r is a shared scalar, λ≡r and allocated_mean_b = base_projection_b·r, i.e. the whole reconciliation degenerates to one per-team multiplier. To isolate the NEW information (opponent pitching) and avoid re-baselining recent form, r is defined in xwOBA space: r = clamp((opp_staff_xwoba_allowed/league_staff_xwoba)^pitch_w, 0.85,1.15), then feat_mult=1+strength·(r−1) bounded like prop_features REST_CAP. PHASE-2 tail: per-batter over-prob = stats.hits_at_least(k, round(n_b), p_b·λ) (binomial survival, stats.py:152) or stats.negbin_at_least (:183) — reuses the exact method-D distributional machinery already in props._distributional_over_rate. Primitives reused: expected_runs_from_factors, negbin/poisson probabilities(), stats.hits_at_least, stats.negbin_at_least, stats.fit_negbin_dispersion, stats._weighted_mean/_std, stats._norm_cdf.

## gate_story
Phase-1 output rides the gate as a per-batter SCALAR feat_mult through the ONLY gate-visible seam (book_line_calibration.project_and_empirical:591-610: projected*=feat_mult; line_eff=line/feat_mult). Implementation: add a `recon` entry to prop_features.FEATURE_REGISTRY (props=frozenset{"batter_hits"}, strengths=(0.0,0.5,1.0), runtime_knob="recon_strength", fn=_recon_fn). recon_fn(ctx,strength) reads ctx["opp_staff_xwoba"] + ctx["league_staff_xwoba"] + pitch_w and returns 1+strength·(r−1); returns 1.0 (no-op, byte-identical to prod) whenever the context field is absent — exactly rest's fail-open contract. The scalar feat_mult per batter = that value. HOW THE SHARED CONTEXT REACHES THE PER-PLAYER OFFLINE OBS: augment join_book_lines_to_actuals (book_line_calibration.py:339) — the obs already carries test_game.opponent + game_date, so attach obs["opp_staff_xwoba"]=game_context.get_asof_team_staff_suppression(opponent, game_date, season) via a memoized per-(opponent,date) index (the Savant endpoint self-caches 24h; enforces cutoff<game_date). project_and_empirical then extends the ctx it hands prop_features.projection_multiplier with that obs field (a 1-line ctx augmentation; strengths_from_params already carries recon_strength via the sweep params). The synthetic sweep (backtest.py:2662) attaches the identical field from the same helper keyed (upcoming_opp, upcoming_date). So NO harness rework — recon uses the SAME obs-augmentation seam the mandate names. Adoption is fully automatic through refit_calibration._best_per_prop/_variant_confirms (:472/:447) + select_method_at_real_lines (:1011): recon ships only if it beats baseline A by ≥ MIN_CALIB_BRIER_GAIN (0.002) on the 50/50 holdout AND both expanding folds — identical to rest/xBA/NegBin-E (all of which shipped nowhere; recon may too, and that is the correct honest outcome). VALIDATED OUTSIDE THE GATE: nothing in Phase 1 — it is 100% gate-gated. Phase 2's tail-shape is gate-visible only as a METHOD (a new distributional candidate wired into _score_abc_real:865 + candidate_methods:1068 with its own reconciled binomial p_dist per row, chosen by select_method_at_real_lines) AND cross-checked by a backtest_props-style separate harness (the matchup_mult precedent). Phase 3's correlation is INVISIBLE to single-prop Brier entirely, so it is validated ONLY by parlay CLV / SGP hit-rate backtest via the parlay copula consumer.

## parity_plan
Three-way parity is preserved by routing ALL three paths through one helper, game_context.get_asof_team_staff_suppression(team,date,season), and one registry fn prop_features._recon_fn — the exact prop_features precedent that keeps rest identical across runtime/sweep/offline. (a) runtime props.py combined_mult (:1251): recon_mult from the runtime GameContext's opponent staff field, fed to the same _recon_fn. (b) synthetic sweep backtest.py:2662-2714: obs-row gets opp_staff_xwoba from the same helper keyed (upcoming_opp,upcoming_date); the calib_obs block already divides the empirical line by feat_mult (:2706) so method A moves too. (c) offline project_and_empirical:591-610: obs["opp_staff_xwoba"] attached in join_book_lines_to_actuals, same helper. Because the factor is TEAM-LEVEL as-of xwOBA (NOT the specific probable starter), it is computable identically offline and live — this is the deliberate design choice that makes recon gate-shippable where matchup_mult was not. The starter-specific matchup_mult stays a runtime-only signal validated separately in backtest_props (its existing precedent) and is REPLACED by recon for batter_hits only when recon ships (see double-counting). Phase 2's pmf/binomial method rides parity through the method axis (same p_dist construction in _score_abc_real and the runtime method-D family). Phase 3's correlation deliberately BYPASSES the projection parity invariant (matchup_mult-style) because it never touches a per-obs projection — it only feeds the parlay copula — and is validated on CLV.

## double_counting_mitigation
The expected-runs xwOBA path already encodes opposing pitching, so recon overlaps matchup_mult (log5 starter, props.py:93) and the team's OWN offense_factor. Mitigations: (1) r is defined to ISOLATE only the opponent-staff term — a ratio (opp_staff_xwoba/league)^pitch_w — never multiplying in the team's own offense_factor, so it cannot re-baseline each batter's recency form (which already carries own-offense signal). (2) RUNTIME REPLACEMENT not stacking: when recon_strength>0 for batter_hits, combined_mult (props.py:1251) drops matchup_mult (set to 1.0) and substitutes recon_mult — recon is the shared team-environment successor to the per-batter starter log5. park_mult/weather_mult/lineup_mult are KEPT (xwOBA is park- and weather-neutral, and lineup exposure is allocation, all orthogonal). xBA blend is kept (batter contact skill, orthogonal to opponent environment). (3) The OFFLINE GATE never double-counts by construction: project_and_empirical applies ONLY recency/venue/opp_defense/xBA/feat_mult — it does NOT apply matchup/park/weather (mandate-confirmed), and the synthetic sweep loop likewise applies park+feat but NOT matchup — so recon is measured against a clean baseline A in both, with no overlapping adjustment present. (4) Phase 2's λ closure REPLACES the mean shift rather than stacking on it (allocated_mean already contains r); the binomial method rebuilds P(>line) from reconciled n·p, exactly as method D deliberately rebuilds from raw hits/AB rather than reusing combined_mult.

## phasing
Phase 0 (inert, ship-safe, no gate needed): create game_context.py building run_mean/staff_suppression from the leakage-safe path + _GC_CACHE guard; add get_asof_team_staff_suppression (one new cached Savant query); refactor mlb_starters negbin/poisson probabilities() to expose the pmf without changing the existing spread scalar; unit tests asserting byte-identical spread output + leakage cutoff. Delivers roadmap "promote matchup_features into a per-game GameContext" (structure only). Phase 1 (FIRST GATE VERDICT): add `recon` to prop_features registry; augment join_book_lines_to_actuals + sweep + runtime; add recon_strength to the refit sweep grid; run `refit_calibration.py --sport mlb`. Delivers "shared run/pace context → per-batter MEAN reconciliation multiplier through the gate." Independently shippable & the first accept/reject/size verdict lands here. Phase 2 (method-axis + backtest_props validated): enrich GameContext with run_pmf + affine team-hits map + per-batter binomial λ closure; expose as a new distributional candidate method in _score_abc_real/select_method_at_real_lines AND a standalone backtest_props harness. Delivers "team-run dist → team-hits → per-batter allocation, bottom-up reconciliation + variance/tail." Phase 3 (parlay/CLV validated): shared-run same-team batter_hits correlation → parlay._pair_correlation (:348, MLB branch currently only handles pitcher ER-vs-K); validate via SGP CLV/backtest, never the single-prop gate. Delivers the correlation layer. Phase 4 (deferred, out of shippable scope): retire analysis.py's three unreconciled run estimates (:400 totals, :136 spread-only, props :93 per-batter) onto the single GameContext pmf. Each phase gate-tests or validates on its own terms before the next begins.

## why_it_wins
It is the only phasing that gets a real confirmation-gate VERDICT out of 3.1 in Phase 1 without any harness rework: recon reuses the exact prop_features feat_mult seam and obs-augmentation plumbing the mandate itself names, so it is validated by the same machinery that already accepted/rejected rest — not a bespoke path. It respects every hard constraint up front (leakage: xwOBA-only source; parity: one shared helper across all three paths; double-count: isolate opponent-staff + replace-not-stack; perf: build-once/cache-per-game on the existing session freeze; no MC). It stages risk correctly — the cheap, gate-legible mean shift ships (or is honestly rejected) first, and only then does it invest in the variance/tail and correlation layers, each validated on the precedent that already exists for exactly that kind of signal (method axis + backtest_props for tails, parlay CLV for correlation). And the ONE GameContext object is built once and monotonically enriched, giving a clean, low-regret path from a shippable v1 scalar to the full bottom-up-reconciled run/hits/correlation vision — including the eventual unification of analysis.py's three warring run estimates — without ever forcing a big-bang rewrite.

## top_risks
- Gate may reject recon outright (like rest/xBA/CSW/NegBin-E) because a TEAM-level staff xwOBA is a weaker per-batter signal than the runtime starter-specific matchup_mult it would replace — accept this as the honest outcome, but it means Phase 1 could ship nowhere and the visible payoff waits for Phase 2's distribution/correlation.
- Replacing matchup_mult with recon at runtime is a net-negative risk if recon ships but is coarser than the starter log5; must A/B the replacement in backtest_props before flipping, and keep matchup_mult as fallback when GameContext is incomplete.
- get_asof_team_staff_suppression adds one Savant query per (season,date); across thousands of offline obs this must be memoized per-date and lean on the endpoint's 24h disk cache, or the refit slows materially.
- Leakage: if any Phase-2 enrichment (lineup, per-batter allocation) silently pulls a season-to-date source into a validation fold, the confirmation folds are invalidated silently — build() must hard-refuse non-xwOBA sources and tag source, with a test asserting the tag.
- Run→team-hits affine constant (b≈1.9) is a league approximation; if mis-fit it biases every batter uniformly — fit a,b offline on completed games and guard with the same completeness gate.
- Double-count regression if a future edit re-adds matchup/park into the offline seam — pin the invariant with a parity test that recon at strength 0 reproduces production byte-for-byte in all three paths.
