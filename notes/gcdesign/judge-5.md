  + Genuinely clean 3-way parity: the scalar is ADDITIVE (a new feature multiplier), computable in all three paths without harness rework — runtime has home/away/is_home (props.py:1251), sweep carries upcoming_opp/upcoming_is_home/player_team_name/upcoming_date (backtest.py:2646-2668), offline via _attach_gamecontext grouping obs by game (obs already carries home_team/away_team via **row, is_home via test_game, book_line_calibration.py:444-450, 527). Strength-0 → 1.0 → byte-identical, the invariant --feature-diag asserts.
  + Correctly declines to touch matchup_mult — pins the starter to neutral 1.0 so matchup_mult keeps owning it — thereby AVOIDING the replace-matchup validity trap that B and C fall into (the offline seam never applies matchup, project_and_empirical only does recency/venue/opp_def/xBA/feat).
  + Best perf/robustness profile: the shipped scalar needs only two team abbrs + date (NO probable-starter, NO lineup fetch), so it is computable over historical backtest dates and has zero stale-lineup memo hazard; no per-player fan-out (one cached fetch per date), no MC.
  + Fail-open and non-MLB safe: complete=False → 1.0, whitelisted to batter_hits, and the registry props-filter no-ops it everywhere else (prop_features.py:117-122, 158-159).
  + Smallest path to a real gate verdict (~120 non-test LOC, no refit/grid/write change) using exactly the seam rest already proved.
FATAL FLAWS:
  ! Overstates orthogonality: the opp_bullpen term overlaps the SHIPPED opp_defense feature, which is built from RUNS ALLOWED per opponent game (backtest.py:2251, 2269-2276) and applied in the same offline seam (book_line_calibration.py:1274) — a run-prevention signal that already prices opposing pitching for batter_hits. A's double-count section names only the own-offense/own-recency overlap and misses this; its 'conservative fallback' (pure opp-bullpen) would make the opp_defense overlap WORSE, not better. Net: gate-native so the confirmation folds adjudicate it, but the signal is more redundant than claimed and more likely to ship nowhere.
  ! EPS/STARTER_SHARE/RUN_CAP are hand-set, unfit constants that bias the mean shift; conservative caps limit damage but a bad EPS could push the redundant signal past the gate on in-sample structure (2-fold _variant_confirms is the only backstop).
  ! home_team/away_team can be None on some book-line rows (book_line_calibration.py:224); _attach_gamecontext must fail-open on those (design says it does, but the group-by key would silently drop those games from the gate sample, shrinking power).
  ! If a batter_hits bucket's shipped method is D, the feature is inert (method-D rate_mult excludes the §2.6 feature, props.py:1284-1285) — a pre-existing gap A inherits, not unique, but limits where the scalar can act.

## Design B — roadmap-faithful full-joint bottom-up GameContext  — score 4
STRENGTHS:
  + Most faithful to the §3.1 vision: retains the run joint that mlb_starters currently discards (the probabilities() inner, mlb_starters.py:410-424) and convolves it into a real shared total distribution — a reusable object, and the totals/spread unification is genuine.
  + Best variance-validation story: wiring a distributional method 'G' into _score_abc_real/candidate_methods gives the gate PARTIAL sensitivity to the tail change (only a mean-preserving shift exactly at the line is invisible), which A defers entirely.
  + Honest, explicit about the correlation layer being Brier-invisible and validated only by parlay-CLV, and about leakage discipline (mu_R as-of, rho a committed constant).
  + Phase 1 leakage itself is clean (mu_i from each obs's own prior_games, mu_R as-of).
FATAL FLAWS:
  ! FATAL plumbing bug in the shippable Phase-1 gamma: gamma = mu_H_team / S where S = Σ mu_i is summed over ONLY the batters that happen to carry a book line in that game (the obs it has), NOT the 9-man lineup. Offline join_book_lines_to_actuals sees ~2-4 batters per game, so S is a tiny fraction of the team, gamma is systematically inflated and pinned to the [0.7,1.4] clamp — garbage. Runtime, by contrast, uses get_confirmed_lineup (full 9), so runtime gamma ≠ offline gamma and B's own 'runtime gamma == offline gamma' parity test would fail unless the lineup is faked. The validated quantity is not the shipped quantity.
  ! Replace-matchup validity break: B REPLACES matchup_mult+lineup_mult with gamma*slot at runtime, but the offline gate never applies matchup_mult (project_and_empirical does recency/venue/opp_def/xBA/feat only). So the gate measures gamma ADDED to a no-matchup baseline while runtime SWAPS matchup for gamma — the Brier gain the gate reports does not describe the live change, and matchup_mult's separately-validated live value is discarded on a gate that never saw it.
  ! Wrongly justifies bypassing sweep parity: claims the sweep 'cannot construct a GameContext' because it carries no opposing-team structure, but the sweep DOES carry upcoming_opp/upcoming_is_home/player_team_name/upcoming_date (backtest.py:2646-2668) — a team-level scalar is computable there. Only B's lineup-sum gamma is not, and that is a consequence of B's design choice, not an intrinsic gap. Result: needless 2-way parity, and the 2-way it keeps is broken by the partial-lineup denominator above.
  ! Gamma also overlaps the SHIPPED opp_defense (runs allowed, backtest.py:2269-2276) since mu_R encodes opposing staff — same redundancy as A but stacked with the two flaws above.
  ! Heaviest scope (~1030 LOC); the correlation payoff (Phase 4) depends on DK closing-line capture that memory records as decided-but-NOT-built, so the one layer that motivates a joint model is unvalidatable for now.

## Design C — Shared-Environment Reconciliation, Phased  — score 6
STRENGTHS:
  + Cleanest scalar parity of the three that use a team ratio: recon = (opp_staff_allowed/league)^pitch_w has NO lineup-sum dependency, so it is computable identically in runtime, sweep, and offline via one shared helper keyed (opp,date) — routed through the same prop_features fn as rest (avoids B's partial-lineup bug entirely).
  + Disciplined leakage handling: build() hard-refuses season-to-date sources and carries a source='expected_runs_xwoba' tag asserted by a test; the new as-of staff query enforces cutoff<game_date. Correctly bans get_team_offense_splits/get_team_bullpen_quality/get_pitcher_quality.
  + Well-staged risk: gate-legible mean shift first, tail on the method axis + backtest_props, correlation on parlay-CLV — each layer validated on the precedent that fits it. Honest that Phase 1 may ship nowhere.
  + Cache/fail-open design is sound: build-once per (home,away,date) on the existing session freeze, TTL split live vs final so a stale probable/lineup can't pin a game, 1.0 no-op when the field is absent, whitelisted to batter_hits.
FATAL FLAWS:
  ! Phase-1 recon is the MOST double-counted signal of the three: opp_staff-allowed overlaps BOTH matchup_mult (the log5 starter, props.py:93) AND the already-SHIPPED opp_defense, which is literally opponent runs allowed (backtest.py:2251, 2269-2276) applied in the same offline seam (book_line_calibration.py:1274). C keeps opp_defense (never drops it) so recon is near-duplicate of a feature already in the gate — likely it either fails MIN_CALIB_BRIER_GAIN or merely substitutes for opp_defense.
  ! Same replace-matchup validity gap as B: C drops matchup_mult at runtime when recon ships, but the offline gate never had matchup — so the validated delta (recon added to no-matchup baseline) ≠ the shipped delta (recon instead of matchup). C flags 'A/B in backtest_props before flipping' but still frames the replacement as clean; it is not.
  ! Adds a NEW Savant query per (season,date) via get_asof_team_staff_suppression — an extra network dependency on the calibration path that must be memoized per-date or it materially slows the refit (C flags this, but it is real cost A avoids by reusing the existing bullpen/offense fetch).
  ! Run→team-hits affine constant b≈1.9 and pitch_w are league approximations; a mis-fit b biases every batter uniformly (C notes this, guarded only by the completeness gate).
  ! Phase-3 correlation, like B, depends on the unbuilt DK closing-line capture for its only validator.
